# Cartoon studio

> **In the gss-lms repository:** the kit in `scripts/toons/` is a copy from servo-pos with the school cast (`K.principal`, `K.dube`, `K.learner`, `K.bursar`, `K.registrar`, `K.acm`, `K.mom`, `K.gogo`), `K.appScene` (app rows timed to the narrator's line), `K.gssEnd` (end card with the demo role) and a School News desk title. GSS-LMS plan, cast, truth notes and posting order: `docs/toons/PLAN.md`; captions: `docs/toons/captions.md`; all voice lines: `scripts/toons/termux-gss.sh`. GSS claims: online applications and messages are Standard plan and up; never promise email, WhatsApp or push notices, card payments or installers; say "demo data".

> **In the servo-pos repository:** the kit is a copy; its source of truth is `gee-highness/venda-khona` (`scripts/toons/`, this skill, `docs/studio/`). Servo's own guide and post captions: `docs/toons/README.md`; the shared plan: `docs/toons/PLAN-venda-khona-copy.md`. Make kit changes in venda-khona first, then copy them here.

A code-driven cartoon studio: every picture is drawn in SVG by small JavaScript functions, rendered frame by frame with Playwright, voiced with Microsoft Edge voices (generated by the user in Termux), scored with synthesised sound effects and music, and cut into every format the platforms want. Because everything is code, a joke, a price, a voice line or a whole art style can change in minutes and re-render.

## Before you start (every time)
1. Read `references/lessons.md` (what went wrong before and how it was fixed) and `references/feedback.md` (what the user said, what performed). They override anything below.
2. Read the brand's plan: Venda Khona and Servo use `docs/toons/PLAN.md` (episodes, cast, scripts) and `docs/studio/IDEAS.md` (series, shorts, status). The market facts are in `docs/studio/MARKET.md`.
3. Servo work must also follow `servo-pos/docs/POSTING_PLAN.md` (offer wording exactly, "Standard plan and up" for the restaurant's own app, payroll is Multi-branch only, never "works offline", "demo data" on demo screens).

## The standard (set by the user)
**The humour in every video must be the best it can be, and everything must feel natural and human.** Write to `references/writing.md`. If a line sounds written rather than spoken, rewrite it. If a joke needs explaining, cut it. Never invent numbers, testimonials or features the app does not have: check the app's feature list (the clip scripts in `docs/footage/CLIPS.md` and `servo-pos/ads/footage/CLIPS.md`) before promising anything.

## The workflow
1. **Plan**: pick the format (`references/platforms.md`) and the art style (`references/styles.md`). Write the script as voice lines first (who, text), with the picture for each line and a truth note for every product claim.
2. **Voices**: put the lines in the episode file (`EP.voice`), then `node scripts/toons/voice.cjs <id>` prints a Termux block; for a batch, write one script like `scripts/toons/termux-batch3.sh` (one folder per episode, one zip, skips files that already exist). The user pastes it, then sends a zip. Unzip into a fresh folder, **check every file has a size above zero** (empty files happen; give the user a retry block for just those), copy to `scripts/toons/voice/<id>/NN.mp3`.
3. **Draw**: copy the closest existing episode (`ep/vk04.js` for Venda Khona, `ep/sv03.js` for Servo) and use automatic timing (`auto: true`): scenes start at a line (`s: lineIndex`), captions and sound effects are tied to lines. Reuse the kit (`K.news`, `K.ownApp`, `K.devices`, `K.end`, the cast, props, `K.goat`). Details in `references/pipeline.md`.
4. **Check before rendering**: `node scripts/toons/engine.cjs <id> --stills 3,9,15,...` (one still per scene) and look at every still. Do not judge a scrolling ticker from stills joined side by side (frame edges meet and look like garbled text: crop one frame at full size instead).
5. **Render**: `node scripts/toons/engine.cjs <id> [--style chalk]` (about 2 minutes; two renders can run in parallel on four cores). Then look at the contact sheet `toons/out/<id>-sheet.jpg`, confirm sound with `ffmpeg ... -af volumedetect`, and that no voice line overlaps the next (the engine prints each line's start and end).
6. **Cut and package**: 15-second cut-downs with `node scripts/toons/cutdowns.cjs <id>` (lines chosen in `scripts/toons/cuts.json`); YouTube compilations with `node scripts/toons/compile.cjs <name> "<Title: Subtitle>" <ids...>`; thumbnails come with the compilation; posters with `--stills` on a strong frame. Deliver in one zip per batch when it fits (about 250 MB at most per file sent): `1080x1920/`, `WhatsApp-720p/`, `captions.md`, numbered in posting order.
7. **Record and improve** (do not skip): add the episode's status and caption to the brand docs; write anything new you learnt to `references/lessons.md`; write the user's reactions and any performance numbers to `references/feedback.md`; if you made a new style, kit function or format, add it to the matching reference file. Commit and push; update main when the user asks. Mirror Servo changes to the `servo-pos` repository (`scripts/toons/`, `docs/toons/`).

## How the skill grows
- **New art style**: add an entry to `STYLES` in `scripts/toons/lib.js` (colours, paper, line wobble, grain, optional glow or paper shadow), render the comparison sheet (three frames in every style), and describe it in `references/styles.md` with when to use it. Ideas waiting to be built are listed there.
- **New character or prop**: add it to the kit `K` in `lib.js` so every later episode can use it; list it in `references/pipeline.md`.
- **New format**: add a tool next to `cutdowns.cjs` and `compile.cjs`, document it in `references/platforms.md`.
- **New brand or channel**: copy one episode, set `brand`, `accentOnInk`, `url`, `logoFile`, and add the brand's rules to `references/feedback.md` (what may and may not be claimed).
- **Learning from results**: when the user shares views, shares or clicks per post (each post has a link tag such as `vk-n04`), log them in `feedback.md` and let them steer the next batch: more of the series, styles and jokes that worked.

## Hard rules
- Captions always on; vertical 1080x1920; the hook lands in the first 3 seconds.
- Say "Cartoon shop" / "Cartoon restaurant" on end cards; "demo data" on demo screens.
- No politics, monarchy, religion as a joke, tribal or national stereotypes, xenophobia, real people or businesses, load-shedding jokes (dated). Local-language lines only after a native speaker checks them.
- The cloud session cannot reach the Edge voices; the user makes them in Termux. Never fake a voice or ship a video with a silent line.
- Never claim you listened to the audio: you can only measure it. Say so, and ask the user to judge the sound.
